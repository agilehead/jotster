# Issue 1: Source-package bindings drop inherited class members

## Status

- confidence: high
- category: Tsonic source-package bindings defect
- impact: blocks consumer packages from using inherited base-class API

## Summary

`JotsterDbContext` extends EF Core `DbContext`, but when Jotster core is consumed through Tsonic-generated source-package bindings, inherited `DbContext` members are not visible in downstream packages.

The result is that real API members such as:

- `SaveChangesAsync(...)`
- `Dispose()`

disappear from the generated `$instance` type used by consumer packages.

## Source shape

File:

- `/home/jester/repos/agilehead/jotster/packages/core/src/db/jotster-db-context.ts`

Relevant code:

```ts
export class JotsterDbContext extends DbContext {
  get Tenants(): DbSetQuery<Tenant> {
    return asinterface<DbSetQuery<Tenant>>(this.Set<Tenant>());
  }

  get Users(): DbSetQuery<User> {
    return asinterface<DbSetQuery<User>>(this.Set<User>());
  }

  constructor(options: DbContextOptions) {
    super(options);
  }
}
```

Important fact:

- `JotsterDbContext` inherits from `DbContext`
- it does **not** redeclare `SaveChangesAsync` or `Dispose`
- that is normal and correct source code

## What the consumer binding should expose

Because `JotsterDbContext` is a `DbContext`, consumer packages should be able to write:

```ts
const db = new JotsterDbContext(options);
await db.SaveChangesAsync();
db.Dispose();
```

Those are inherited members of the base class, and they are part of the actual usable API.

## What the generated source binding actually exposes

File:

- `/home/jester/repos/agilehead/jotster/packages/core/dist/tsonic/bindings/Jotster.Core.db/internal/index.d.ts`

Actual generated shape:

```ts
export interface JotsterDbContext$instance extends DbContext {
  readonly __tsonic_type_Jotster_Core_db_JotsterDbContext: never;
  readonly Tenants: __TsonicExt_Ef<__TsonicExt_Linq<DbSet<Tenant>>>;
  readonly Users: __TsonicExt_Ef<__TsonicExt_Linq<DbSet<User>>>;
  readonly ApiKeys: __TsonicExt_Ef<__TsonicExt_Linq<DbSet<ApiKey>>>;
  ...
}
```

What is missing:

- `SaveChangesAsync(...)`
- `Dispose()`

Even though the interface says `extends DbContext`, the consumer typechecking path is not treating those inherited members as actually available.

## Why this is a Tsonic issue

This is not a Jotster authoring problem.

The class inheritance is real.
The runtime API is real.
The downstream package is consuming a first-party source package generated by Tsonic.

If source-package bindings are the compiler-owned contract for first-party libraries, then inherited base-class members must remain visible to consumers.

Otherwise, downstream packages cannot typecheck code that is valid against the actual runtime/API surface.

## Minimal repro

### Library

```ts

export class MyContext extends DbContext {
  constructor(options: DbContextOptions) {
    super(options);
  }
}
```

### Consumer

```ts
const db = new MyContext(options);
await db.SaveChangesAsync();
db.Dispose();
```

### Expected

- inherited `DbContext` members are available

### Current behavior

- generated source-package consumer type does not expose them correctly

## Expected fix direction

Tsonic source-package binding generation should preserve inherited instance members in the consumer-visible type contract.

It does not have to literally duplicate every base member into the emitted interface, but the final downstream typechecking behavior must expose the inherited API correctly.

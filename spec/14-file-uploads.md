# 14 - File Uploads

## Overview

The file uploads module handles file upload and attachment management for Jotster. Files uploaded by users are stored on the local filesystem (with S3-compatible storage planned for later). Each uploaded file is tracked as an `attachment` record. Attachments are linked to messages via a many-to-many join table (`attachment_message`), enabling the system to track which messages reference which files.

The upload flow returns a server-relative URL that can be embedded in message content. The serve endpoint is outside the `/api/v1/` namespace -- files are served at `/user_uploads/{realm_id_str}/{path}` to match Zulip's URL structure. Access control ensures that only users who can see the referencing message (i.e., are in the relevant channel or DM group) can download the file.

Zulip also supports the tus protocol (POST /api/v1/tus) for resumable large file uploads. This is marked as optional and will be implemented later.

Package: `uploads`

## API Endpoints

| Method | Path                                        | Description                                      |
| ------ | ------------------------------------------- | ------------------------------------------------ |
| POST   | /api/v1/user_uploads                        | Upload a file, returns the server-relative URL   |
| GET    | /user_uploads/{realm_id_str}/{path}         | Serve an uploaded file (not under /api/v1/)      |
| GET    | /api/v1/attachments                         | List the current user's uploaded files            |
| DELETE | /api/v1/attachments/{attachment_id}         | Delete an attachment                              |
| POST   | /api/v1/tus                                 | Resumable upload via tus protocol (optional/later) |
| GET    | /api/v1/user_uploads/download/{realm_id_str}/{filename} | Download a file (forces download vs inline display) |
| GET    | /api/v1/user_uploads/thumbnail/{realm_id_str}/{filename}/{thumbnail_format} | Get a thumbnail of an uploaded image |
| GET    | /api/v1/user_uploads/temporary/{token}/{filename} | Serve a file via temporary unauthenticated URL |
| GET    | /api/v1/avatar/{user_id}                    | Get user avatar by user ID                       |
| GET    | /api/v1/avatar/{email}                      | Get user avatar by email                         |
| GET    | /api/v1/avatar/{user_id}/medium             | Get medium-sized avatar                          |
| GET    | /api/v1/avatar/{email}/medium               | Get medium-sized avatar by email                 |
| GET    | /api/v1/thumbnail                           | Serve image thumbnail                            |

### POST /api/v1/user_uploads

Upload a file as multipart form data. Returns the server-relative URL for the uploaded file.

**Request:** Multipart form data with a single file field.

**Response:**
```json
{
  "result": "success",
  "msg": "",
  "uri": "/user_uploads/{realm_id_str}/{path_id}"
}
```

### GET /user_uploads/{realm_id_str}/{path}

Serves the uploaded file. Requires authentication. The server validates that the requesting user has access to at least one message that references this attachment, or is the uploader, or is an admin.

### GET /api/v1/attachments

Returns a list of all files uploaded by the current user.

**Response:**
```json
{
  "result": "success",
  "msg": "",
  "attachments": [
    {
      "id": "...",
      "name": "document.pdf",
      "path_id": "abc123def.pdf",
      "size": 104857,
      "create_time": 1700000000000,
      "messages": [
        { "id": "msg1", "date_sent": 1700000000 }
      ]
    }
  ],
  "upload_space_used": 1048576
}
```

### DELETE /api/v1/attachments/{attachment_id}

Deletes an attachment. Only the uploader or an admin can delete. Removes the file from storage and the database record.

### GET /api/v1/user_uploads/download/{realm_id_str}/{filename}

Downloads an uploaded file with `Content-Disposition: attachment`, forcing a download rather than inline display in the browser. Authentication and access control are the same as the standard serve endpoint.

### GET /api/v1/user_uploads/thumbnail/{realm_id_str}/{filename}/{thumbnail_format}

Returns a thumbnail of an uploaded image. The `thumbnail_format` parameter specifies the desired size/format (e.g., `"300x200"`). Only applicable to image files. Returns 404 for non-image files or if the thumbnail cannot be generated.

### GET /api/v1/user_uploads/temporary/{token}/{filename}

Serves a file via a temporary unauthenticated URL. The `token` is a short-lived, single-use token generated by the server. Used for sharing files in contexts where authentication headers cannot be sent (e.g., embedding in emails). Returns 403 if the token is expired or invalid.

### GET /api/v1/avatar/{user_id}

Returns the avatar image for the specified user. Falls back to a generated default avatar if no custom avatar has been uploaded. Supports `?s={size}` query parameter for sizing.

### GET /api/v1/avatar/{email}

Returns the avatar image for the user with the specified email address. Same behavior as the user_id variant.

### GET /api/v1/avatar/{user_id}/medium

Returns the medium-sized version of the user's avatar (suitable for profile views and cards).

### GET /api/v1/avatar/{email}/medium

Returns the medium-sized avatar for the user with the specified email address.

### GET /api/v1/thumbnail

Serves an image thumbnail. Accepts query parameters `url` (the upload URL to thumbnail) and `size` (desired thumbnail dimensions).

## Data Model

### `attachment`

| Column       | Type   | Constraints                          | Description                              |
| ------------ | ------ | ------------------------------------ | ---------------------------------------- |
| id           | string | PK                                   | Nanoid                                   |
| tenant_id    | string | FK -> tenant, NOT NULL               | Tenant scope                             |
| user_id      | string | FK -> user, NOT NULL                 | The user who uploaded the file           |
| file_name    | string | NOT NULL                             | Original filename as uploaded            |
| path_id      | string | NOT NULL                             | Storage path identifier, unique random string + original extension |
| size         | int    | NOT NULL                             | File size in bytes                       |
| content_type | string | NOT NULL                             | MIME type (e.g., `"application/pdf"`, `"image/png"`) |
| is_web_public| int    | NOT NULL, default 0                  | 1 if accessible without authentication  |
| created_at   | int    | NOT NULL                             | Unix milliseconds                        |

**Indexes:**

| Name                          | Columns                       | Purpose                                 |
| ----------------------------- | ----------------------------- | --------------------------------------- |
| uq_attachment_path_id         | (tenant_id, path_id)          | UNIQUE -- each path_id is unique per tenant |
| ix_attachment_user             | (tenant_id, user_id, created_at) | List attachments uploaded by a user  |

### `attachment_message`

Many-to-many join table linking attachments to the messages that reference them.

| Column        | Type   | Constraints                         | Description                              |
| ------------- | ------ | ----------------------------------- | ---------------------------------------- |
| attachment_id | string | FK -> attachment, NOT NULL          | The attachment                           |
| message_id    | string | FK -> message, NOT NULL             | The message referencing the attachment   |

**Primary key:** (attachment_id, message_id)

**Indexes:**

| Name                                | Columns                     | Purpose                                  |
| ----------------------------------- | --------------------------- | ---------------------------------------- |
| ix_attachment_message_message       | (message_id)                | Find all attachments referenced by a message |

## Storage Layout

Files are stored on the local filesystem at:

```
{uploads_dir}/{tenant_id}/{path_id}
```

The `path_id` is generated as a random string (nanoid) concatenated with the original file extension. For example, an upload of `report.pdf` might produce `path_id = "V1StGXR8_Z5jdHi6B-myT.pdf"`.

The `uploads_dir` is configured in `jotster.config.json`:

```json
{
  "uploadsDir": "./uploads"
}
```

## Repository Interface

```
createAttachment(tenantId, userId, fileName, pathId, size, contentType)
  -> Result<Attachment>
```
Insert a new attachment record. Returns the created attachment.

```
getAttachment(tenantId, attachmentId)
  -> Result<Attachment | null>
```
Fetch an attachment by its ID within the tenant.

```
getAttachmentByPath(tenantId, pathId)
  -> Result<Attachment | null>
```
Fetch an attachment by its storage path ID within the tenant. Used when serving files.

```
getUserAttachments(tenantId, userId)
  -> Result<Attachment[]>
```
Fetch all attachments uploaded by a specific user, ordered by `created_at` descending.

```
deleteAttachment(tenantId, attachmentId)
  -> Result<void>
```
Delete an attachment record from the database.

```
linkAttachmentToMessage(attachmentId, messageId)
  -> Result<void>
```
Insert a row into `attachment_message` linking an attachment to a message. Ignores duplicates.

```
getAttachmentsForMessage(messageId)
  -> Result<Attachment[]>
```
Fetch all attachments linked to a specific message via the `attachment_message` join table.

```
getMessagesForAttachment(attachmentId)
  -> Result<{ id: string, date_sent: number }[]>
```
Fetch all messages that reference a specific attachment. Used for the attachments list endpoint.

## Domain Functions

### uploadFile

Validate that the uploaded file does not exceed the configured maximum file size. Validate that the MIME type is not in the blocked list (if any). Generate a unique `path_id` using nanoid + original file extension. Write the file to `{uploads_dir}/{tenant_id}/{path_id}`, creating intermediate directories as needed. Create the attachment record in the database via `createAttachment`. Return the server-relative URL `/user_uploads/{realm_id_str}/{path_id}`. Emit an `attachment` event with `op: "add"`.

### serveFile

Extract the `path_id` from the request URL. Look up the attachment by path via `getAttachmentByPath`. If not found, return 404. If `is_web_public` is 1, serve the file without further checks. Otherwise, validate that the requesting user has access: either they are the uploader, or they are an admin, or they are a member of a channel or DM group containing at least one message that references this attachment. If access is denied, return 403. Set appropriate `Content-Type` and `Content-Disposition` headers. Return the file from storage.

### deleteAttachment

Validate that the requesting user is the uploader or an organization admin. Look up the attachment by ID. Delete the file from the filesystem at `{uploads_dir}/{tenant_id}/{path_id}`. Delete the attachment record and all associated `attachment_message` rows from the database. Emit an `attachment` event with `op: "remove"`.

### linkAttachmentToMessage

Called during message send/edit when the rendered content contains upload URLs. Parse the rendered HTML for `/user_uploads/` URLs. For each URL, resolve the `path_id` and look up the attachment. If found, call `linkAttachmentToMessage` on the repository. Emit an `attachment` event with `op: "update"` for each newly linked attachment.

## Events

### `attachment` with `op: "add"`

Emitted when a file is uploaded. Contains:
- `type`: `"attachment"`
- `op`: `"add"`
- `attachment`: object with `id`, `name`, `path_id`, `size`, `create_time`
- `upload_space_used`: total bytes used by the uploader

### `attachment` with `op: "remove"`

Emitted when an attachment is deleted. Contains:
- `type`: `"attachment"`
- `op`: `"remove"`
- `attachment`: object with `id`
- `upload_space_used`: updated total bytes used by the uploader

### `attachment` with `op: "update"`

Emitted when an attachment is linked to a new message. Contains:
- `type`: `"attachment"`
- `op`: `"update"`
- `attachment`: object with `id`, `name`, `path_id`, `size`, `create_time`, `messages`
